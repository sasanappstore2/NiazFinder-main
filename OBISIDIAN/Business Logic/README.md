# Business Logic

## هدف
قوانین کسب‌وکاری غیربدیهی که در کد پراکنده‌اند ولی باید یک‌جا مستند شوند — چیزهایی که یک مهندس جدید یا ایجنت AI بدون خواندن این سند احتمالاً اشتباه می‌گیرد.

## قوانین کلیدی (استخراج‌شده از CLAUDE.md و کار این جلسه)
1. **کاربر عادی هیچ‌وقت برای ثبت نیاز پول پرداخت نمی‌کند** — مدل درآمدی فقط سمت کسب‌وکار است (Pay-as-you-go + Wallet). منبع: [[../10_Product_Areas/17_Monetization_Backlog|10_Product_Areas/17_Monetization_Backlog]].
2. **کسب‌وکار فقط برای ارزش واقعی هزینه می‌کند** — فی لید هنگام ارسال واقعی کسر می‌شود، نه هنگام مشاهدهٔ فهرست.
3. **همهٔ پرداخت‌ها از طریق Wallet** — حتی درگاه پرداخت (Zarinpal) فقط برای شارژ کیف پول است، نه پرداخت مستقیم روی هر اکشن.
4. **الگوی idempotent lock-check برای هر عملیات پولی** — هر تابعی که موجودی کیف پول را تغییر می‌دهد باید الگوی `SELECT ... FOR UPDATE` + بررسی idempotency قبل و بعد از قفل را تکرار کند (نمونهٔ مرجع: `src/lib/smart-matching/wallet-lead-fee.ts`).
5. **اعتبار هدیهٔ ثبت‌نام فقط برای کسب‌وکارهای جدید**، نه هر کاربر CLIENT — جلوگیری از سوءاستفادهٔ ساده.
6. **پاداش رفرال مشروط است** — فقط بعد از ثبت‌نام + تکمیل پروفایل + مشاهدهٔ اولین لید، نه صرفاً ثبت‌نام.
